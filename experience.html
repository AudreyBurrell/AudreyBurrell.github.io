Tinker's Puzzle

Tinker's Puzzle is an interactive activity developed for a geometry course. The project was designed to help students learn object transformations on graphs (translation, rotation, and reflections) through moving a puzzle piece from a start location on the graph to a goal location, and then they can see how all the transformations work together at the end.

Objective

Create an engaging activity that helps students develop an understanding of geometric transformations by allowing them to experiment in a free and creative space in a hands-on environment rather than only solving textbook problems which may be hard to visualize.

My role

The assets for the activity were given to me, but after that I designed and developed it to completion, creating the user interface, implementing geometric transformation mechanics, and accessibility. I collaborated with the designer and coworkers to refine the activity based on feedback.

Implementation

This activity was developed in SmartBuilder and also has custom JavaScript. I implemented the transformation logic, animations, and designed the interface to provide clear visual feedback. AI-assisted tools were used to brainstorm the animation logic, mathematical calculations, and debugging approaches.

Challenges

One of the biggest challenges was resolving a complex bug that caused inconsistent behavior in the puzzle's transformation logic. I tested various different approaches to isolate the problem. Solving it strengthened my debugging and perserverance skills and reinforced the importance of breaking problems down into smaller, testable components. It also taught me that solutions are not always found by adding more complex logic. Sometimes the answer is hidden within the design of the system itself.

Spreadsheet Siege

Spreadsheet Siege is an interactive activity designed for a computer science course to help students become more comfortable using spreadsheets. Before starting the activity, students are instructed to create a spreadsheet to represent their board and ships. Once starting, they play against a pirate in a battleship-like game. Instead of generating ships randomly, the pirate selects one of several predefined baord layouts each time the activity begins. Then, the pirate uses math to logically decide which location on the board it should attack next.

Objective

Create an engaging activity that helps students build confidence using spreadsheets in a hands-on environment.

My role

The assets for the activity were given to me, but after that I designed and developed it to completion. I created the user interface, implemented logic for the pirate choosing attack points, and accessibility. I collaborated with the designer and coworkers to refine the activity based on feedback.


The completed activity contained over 14,000 SmartBuilder logic blocks, requiring careful organization and debugging to maintain functionality and making it one of the largest and most complex interactives I have developed.

Implementation

This activity was developed completely in SmartBuilder, with some AI-assistance for brainstorming pirate logic. I implemented the pirate choosing logic using math and giving each place on the board a number (1-100). The pirate starts out choosing random pieces until it gets a hit. When that happens, it will choose from a list of squares directly next to the hit (removing places that either has a piece already or that don't exist) until it gets another hit. In that case, the pirate will keep going in that direction until it sinks a ship, or hits another piece/wall after which it will start guessing in the opposite direction until it sinks a ship.

Challenges

One of the biggest challenges that I faced was making this activity screen-reader accessible. I needed a way for screen readers to read the correct information and so when it was the users turn, they wouldn't have to cycle through the whole board with their keyboard to get to a piece to press (which would be incredibly annoying if they wanted to guess J-10 or another far location). To solve this, I included hidden buttons on various parts of the activity (like on the starts of each column) so the user could jump to a row before choosing a number. This taught me how to use hidden buttons/text to assist with users using keyboards and screen readers and how to design while keeping accessibility in mind.

Energy Device

Energy Device is an interactive activity designed for a science course to help students become familiar with how they could put together an energy device and how different pieces/combinations can change the outcome. Users can choose from a shelf of items, such as gears, wire, crank, etc. and after clicking on one, it will snap to the first available location on the board. Afterwards, they can test their device to see how bright the lightbulb can get within 15 seconds. Throughout the activity, the user will be given feedback to help them if they have made a mistake.

Objective

Create an interactive learning experience where students can learn how different components work together within an energy device. The activity was designed to encourage experimentation and problem-solving by allowing students to test different combinations of parts and observe how they affect the device's components. As this was for a completely online course, it also removed the need for students to have the physical items.

My role

I was given the assets, but after that I designed and developed it to completion. I implemented the user interface, implemented logic for determining the next available location for any piece, and accessibility. I collaborated with the designer and coworkers to refine the activity based on feedback.

Implementation

I built it mainly using SmartBuilder, but I used custom JavaScript to determine the location of a piece and how bright the lightbulb could get in 15 seconds, along with custom HTML/CSS for the progress bar that also represented the brightness of the lightbulb. For the movement of each piece, I had a function that could grab every piece that is currently on the board and the piece that the user is trying to move, and it would either return coordinates that the new piece should move to or feedback text. I used AI-assistance for brainstorming piece movement logic and generating the code for the progress bar.

Challenges

The biggest challenge that I faced while developing this activity was determining the location of objects as they are put on the board. I had to move around the pieces and write down their coordinates (as SmartBuilder doesn't have the functionality of creating objects so they all had to be created and in the activity beforehand, even if they are off screen) and determine if any pieces would need to move to get it the other piece to fit visually. I then made sure to keep track of which items are on the board using a list, that way the JavaScript function that I wrote could use that list to determine which pieces were on the board and return the coordinates or error message for the piece the user is currently trying to add.

Rubric Template

This rubric template is an interactive activity designed so students can practice grading an essay, audio, or anything else that is embedded into the canvas page above the activity and then allow them to compare their evaluation with an expert's evaluation. To make this activity more customizable (and allow designers to update it without consistently having to send it back to SmartBuilder team to update), all the information inside this activity was embedded through CSVs.

Objective

Create an interactive activity that allows students to practice evalauting work using a rubric and compare their responses with the expert's evaluation. The goal was to give students examples of good essays/audios/whatever is above the activity and bad ones to help prepare them for when they do those assignments. Through the activity, students should be able to better understand grading criteria and expectations. The activity also needed to be easily customizable so any rubric could fit inside it.

My role

I attended a brainstorming meeting about the activity but after that I designed and developed it to finished product. I implemented the grading logic, designed the user interface, and created a flexible CSV-driven system that allows designers to update content without needing to go into the code. I collaborated with instructional designers throughout development to incorporate feedback and insure the template met accessibility and usability standards.

Implementation

I built this activity mainly using SmartBuilder, but the topics on the left-hand side of the rubric were created using custom HTML, CSS, and JavaScript (SmartBuilder can't create or really edit objects once they are on the screen, and the topics could change based on which categories they are supposed to cover). Rather than hard-coding rubric content, I impleented a CSV-driven system that will load in topic information, rubric data, feedback, and expert responses. It is completely screen-reader accessible with hidden off-screen buttons that allow users using screen-readers to jump to categories.

Challenges

One of the biggest challenges was designing the CSV system that could support a wide variety of rubric layouts and content. Separating this information from the activity's code required careful planning and thorough testing. Because of the different kinds of data in this activity (the left side topics, the rubric data, expert response), I had to create several CSVs. To account for different sizes of rubrics, I designed it to have a maximum number of 10 categories and to just hide those that aren't in use. This experience reinforced the concept of making sure software is maintainable and meets the needs of technical and non-technical users.
