Branch Directory Application

Developed for my home branch | June 2026 - Present

A full-stack member directory application designed to help leaders view, search, and organize branch information. The application allows authorized users to quickly find members, view details such as age and most recent talk date, and track speaking assignments.

HTML/CSS JavaScript MongoDB Netlify Functions User Authentication CSV Import AI-assisted

Problem

Managing member information and speaking assignments manually is difficult. Users need a simpler way to search through members and quickly see important information. The tools typically used now do not allow this.

Implementation

I built a full-stack web application using HTML, CSS, and JavaScript for the front-end, with MongoDB and Netlify Functions handling the backend. The application includes member searching, filtering, authentication, and CSV import to make adding large amounts of information easier.


I used AI-assisted development tools such as ChatGPT and Claude as part of my workflow to help brainstorm and debug issues, and improve efficiency while building the application, particularly with the CSS and backend implementation. I maintained responsibility for the design decisions and final code.

Design Decisions

I focused on creating an interface that allowed users to find information quickly without needing to navigate much. I prioritized clear organization, readable information, and simple workflows with clear instructions.

Challenges

One challenge that I had was designing the backend structure. I needed to ensure communication between the front-end and back-end was secure while still being easy to deploy. The answer that I came to was using MongoDB and Netlify Functions.

Results

This application provides leaders with a centralized way to manage and search member information. This project strengthened my confidence in using AI assistance for researching and using tools that I've never used before (such as Netlify Functions).

Once completed, a demo video with fake data will be shown. Because this application manages private member information, the source code is not publicly available.

Cook-a-Book

Developed as a team project as part of CS 256 (Intro to Human-Computer Interaction) at BYU | Oct. 2025 - Dec. 2025

A Figma high-fidelity prototype developed as a team project of an application designed to make it easier for users to save their recipes, find new recipes, and meal plan. We all worked on implementing feedback, but the parts of the application that I mainly worked on were the meal planning section, the settings page, most of the popups, and click-and-reveal items like the dropdown menus.

Figma UI Design User Reviews/User Research Iterative Design Team Project

Problem

Users can find recipes anywhere—on social media, Pinterest, old family cookbooks, etc. It can also be hard to share recipes with others, find new recipes, and organize them. Also, a lot of recipes online will have a lot of ads on them or long stories about the recipes or cook, making it hard to find the recipe on the page.

Implementation

This high-fidelity prototype was built using Figma, but early wireframes were made on whiteboards, index cards, etc. Throughout the project, we incorporated feedback from classmates, the professor, TAs, and potential users to improve navigation, organization, and other elements (ex: the meal planning page was not originally supposed to be there).

Features

Features include being able to add a recipe to various parts of the application (sorted cookbook, unsorted recipe, or community) by scanning an image, using a link, or using text. On any recipe page, the prep time and cook time is displayed at the top with ingredients immediately following, improving quick readability. Recipe information, such as servings and other dietary information is in a dropdown menu to keep the recipe page uncrowded. If there is a story that goes along with a recipe, it will also be in a dropdown menu. Users can scroll through the community page to find new recipes, and plan the meals for each day using the meal planner feature. On the settings page, users can set their notification preferences, change their language, and view other account settings.

Challenges

One of our biggest challenges as a team was making sure that the design layout was intuitive and something we got a lot of feedback on from our users. In beginning prototypes, the icons were harder to decipher and there weren't as many ways to add a recipe. Based on this feedback, we refined the navigation, improved the icons and instructions, and expanded ways that users could add recipes.


One challenge that I faced was getting the dropdowns and other popups (like the popups that come after clicking any + button) to show up on the screen where I wanted them to and to have the popups appear above the rest of the information on the page. This required careful planning of where to place items and some redoing on other pages to make sure they worked across the application.

Results

This high-fidelity prototype addressed the user needs identified during user research and a real-world problem that we researched. The project strengthened my skills in user feedback, collaborating on a team, and designing interfaces from a low-fidelity prototype to a high-fidelity prototype. If I were working on this project again, I would add more features such as dietary information and filters that could make recipe lookup on the community pages better.

Brainstorm-Board

Developed as a personal project | Jan. 2026 - Feb. 2026

A full-stack application designed to give users a virtual whiteboard for brainstorming ideas. Materials that they can use include pre-made templates and tools such as markers, draggable sticky notes, and draggable text boxes. If the user is logged in, they can save their boards to a "library" and access them later. Users can also download/upload boards, whether or not they are logged in.

HTML/CSS React Node.js UI Design User Authentication AI-assisted

Problem

Many online whiteboard tools either require subscriptions to use or have too many advanced features which make the application hard to use. I wanted to create something that could satisfy basic brainstorming needs (like the ones I needed for planning out my books) while giving enough flexibility to still be customizable and usable without being logged in.

Implementation

I built a full-stack web application using HTML, CSS, and React for the front-end, and Node.js for the back-end. This application includes customizable features for the user to use on the whiteboard, user authentication, download/upload board capabilities and persistent back-end storage that allows users to save and continue editing their boards no matter their authentication status.


I used AI-assisted development tools such as ChatGPT and Claude throughout development to brainstorm implementation approaches, debug issues, and improve efficiency. These tools were mainly used for CSS styling and React component setup. I also used it for drag-and-drop interactions, file upload/download functionality, and back-end implementation. I remained responsible for the application's design decisions, testing, and final code, frequently modifying or extending AI-generated suggestions to meet the project's needs.

Design Decisions

I wanted to make the interface feel open and only include essential, clearly labeled tools for what the user can choose from so users could focus on brainstorming rather than learning complicated controls. But there are still plenty of things that the user could choose from/customize (like the text color, sticky note color, size, templates, etc.) to give the users plenty of creativity and to make the application usable with different planning styles.

Challenges

The first challenge that I faced was that I had limited experience working with the HTML Canvas API, so getting the drawing logic to work was tricky, but luckily I had an older project that I could look back to. Then I had to figure out how to make the template appear behind the editable canvas so the user couldn't erase parts of the template when erasing their drawing and how to make objects like the text boxes and sticky notes draggable.


Another challenge was designing a system to manage the application's state while allowing each object to remain independent and available. The system also needed to perserve each object's position, color, and size so boards could be saved and reopened without losing functionality.

Results

This application provides users with a workspace for brainstorming and organizing ideas. Through this project, I was better able to understand React, gained experience managing application state, and learned more about JSON and persistent data storage. I also learned that AI can be used to help brainstorm different ways to code something before tackling the problem, which was especially helpful for the draggable text boxes/sticky notes and the templates. If I were working on this project again, I would try to keep the React components in separate files to make the code cleaner.
